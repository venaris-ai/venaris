🧠 Venaris – Daily Delta

Date: 2026-03-30
Session Goal: Revier als verpflichtenden operativen Scope sauber absichern und die Revier-UX auf eine inline bearbeitbare Management-Ansicht umstellen.

✅ Done Today

- Revier-Domänenregel fachlich und technisch festgezogen: jede Kamera braucht zwingend ein Revier, neue Organisationen erhalten automatisch ein Default-Revier.
- Supabase-Datenmodell für Reviere erweitert und abgesichert: `reviers.is_default` eingeführt, genau ein Default-Revier pro Organization modelliert und Default-Revier gegen Löschung geschützt.
- Backfill für Bestandsdaten umgesetzt: bestehende Orgas ohne Revier erhielten ein Default-Revier; bestehende Orgas mit Revieren bekamen genau ein Default-Revier zugewiesen.
- Default-Revier-Fläche für Bestandsdaten von 1 ha auf 450 ha angehoben.
- Trigger-Funktion `create_default_revier_for_organization()` so angepasst, dass neu erzeugte Organisationen automatisch ein Default-Revier mit 450 ha erhalten.
- `/orga/reviere` von einer reinen Listen-/Edit-Link-Seite auf eine inline bearbeitbare Management-Ansicht nach Members-Muster umgebaut.
- Neue Revier-Row-Komponenten eingeführt: `RevierRowControls` und `RevierRowActions`.
- Revier-Übersicht UX bewusst reduziert: nur noch Name, Fläche, Status sowie Save/Delete-Aktionen; Region, Land, Notizen und gelber Hinweisblock aus der führenden Übersicht entfernt.
- Default-Revier-Löschung auch im UI sichtbar abgesichert: grauer Papierkorb mit Tooltip statt aktiver Delete-Aktion.
- `/orga/reviere/new` an die reduzierte Revier-MVP-Logik angepasst; nur noch Name, Fläche und Status werden erfasst.
- `/cameras/new` auf verpflichtende Revier-Auswahl umgestellt.
- Kameraanlage wählt jetzt standardmäßig das Default-Revier der aktiven Organisation vor.
- Leere „No revier assigned“-Option aus dem Kamera-Create-Flow entfernt.
- Kamera-Create-Flow so gehärtet, dass immer eine echte `revierId` an die Create-Route übergeben wird.
- `npm run build` lief nach den App-Änderungen sauber durch.

🟡 Changed System Behavior

- Neue Organisationen erhalten jetzt automatisch ein Default-Revier mit `is_default = true` und `area_ha = 450`.
- Das Default-Revier ist fachlich editierbar, aber nicht löschbar.
- Revierverwaltung erfolgt jetzt primär inline auf `/orga/reviere` statt über einen separaten Edit-Flow.
- Die führende Revier-MVP-UX fokussiert jetzt bewusst nur auf Name, Fläche und Status.
- Kamera-Erstellung erlaubt kein revierloses Anlegen mehr; Revier ist im UI jetzt Pflicht statt optional.
- Kamera-Erstellung verwendet standardmäßig das Default-Revier der aktiven Organisation als Vorauswahl.

🔴 New Problems / Risks

- `/api/cameras/create` verlässt sich weiterhin primär auf die DB-/RPC-Wahrheit; die UI ist jetzt sauber, aber die serverseitige Route validiert `revierId` nicht zusätzlich explizit als Pflichtfeld.
- Der separate Legacy-Edit-Flow `/orga/reviere/[id]/edit` existiert weiterhin parallel zur neuen Inline-Management-Ansicht und könnte später inkonsistent wirken, wenn er nicht nachgezogen oder stillgelegt wird.
- Region, Land und Notizen bleiben im Datenmodell erhalten, sind aber in der führenden Revier-UX aktuell bewusst ausgeblendet; spätere Boundary-/Geometrie-Arbeit muss diese Felder wieder fachlich einordnen.
